## ✅ Summary

**4-Agent Pipeline** — a six-step agent pipeline (Researcher → Verifier → Planner → Fixer → Security Verifier → Test Generator) that operates on a small Express sample app with seeded defects. The pipeline locates the defects, plans the fix, applies it, security-reviews the change, and generates unit tests — **all from a single Claude Code conversation command**. Built with **Node.js + Express + Jest**, in-memory store, Claude Code **subagents** under `.claude/agents/` orchestrated by the Claude Code conversation runner.

### Agents

| Agent | Model | Required? | Output |
|-------|-------|-----------|--------|
| `bug-researcher` | `sonnet` | upstream | `research/codebase-research.md` |
| `research-verifier` | `opus` | ⭐ required | `research/verified-research.md` |
| `bug-planner` | `sonnet` | upstream | `implementation-plan.md` |
| `bug-fixer` | `sonnet` | ⭐ required | `fix-summary.md` + edits in `src/` |
| `security-verifier` | `opus` | ⭐ required | `security-report.md` (read-only) |
| `unit-test-generator` | `sonnet` | ⭐ required | `test-report.md` + new `tests/*.test.js` |

Agents communicate **exclusively through files** under `context/bugs/<bug-id>/`. There is no shared in-memory state.

### What's inside

**Task 1 — Research Verifier (required)**

`agents/research-verifier.agent.md` + `.claude/agents/research-verifier.md` (Claude Code subagent, model `opus`). Verifies every `file:line` reference and snippet from the researcher's output against the actual source, grades research quality per the `research-quality-measurement` skill, and writes `verified-research.md` with the structure mandated by the skill (Verification Summary, Verified Claims, Discrepancies Found, Quality Assessment, References). A `FAIL` verdict is a hard stop for the pipeline.

**Task 1.2 — Skill: research quality measurement**

`skills/research-quality-measurement.md` — five-level rubric (`EXCELLENT / GOOD / ACCEPTABLE / POOR / UNUSABLE`), mandatory verification checklist (5 checks per claim), and the required output structure. The Research Verifier must cite the skill in its output.

**Task 2 — Bug Fixer (required)**

`agents/bug-fixer.agent.md` + `.claude/agents/bug-fixer.md` (model `sonnet`). Executes `implementation-plan.md` literally — applies each before/after snippet, runs `npm test` after each step, and stops on the first failing test. Writes `fix-summary.md` documenting every change with `file:line` and the test outcome.

**Task 3 — Security Verifier (required)**

`agents/security-verifier.agent.md` + `.claude/agents/security-verifier.md` (model `opus`, **read-only**). Reviews only the files changed by the Bug Fixer. Applies a security checklist (injection, secrets, insecure comparisons, missing validation, auth/authz gaps, XSS/CSRF, unsafe deps) and produces `security-report.md` with severity (`CRITICAL/HIGH/MEDIUM/LOW/INFO`), `file:line`, and remediation per finding. Cannot edit code.

**Task 4 — Unit Test Generator (required)**

`agents/unit-test-generator.agent.md` + `.claude/agents/unit-test-generator.md` (model `sonnet`). Generates Jest tests covering **only** the code changed by the Bug Fixer, following the `unit-tests-FIRST` skill. Runs `npm test` and writes `test-report.md` with the FIRST checklist and the real test summary.

**Task 4.2 — Skill: unit tests FIRST**

`skills/unit-tests-FIRST.md` — defines **F**ast, **I**ndependent, **R**epeatable, **S**elf-validating, **T**imely, plus coverage rules (regression + happy path per defect, hardened-path test for security fixes), file/naming conventions, and the required `test-report.md` structure.

**Task 5 — Sample mini application**

Minimal Express API in `src/` backed by an in-memory user store. Routes: `GET /users?page=N`, `GET /users/:id`, `POST /users/login`. Three defects seeded and documented in `context/bugs/001-seeded/bug-context.md`:

| # | Type | Location | Issue |
|---|------|----------|-------|
| 1 | Logic | `src/routes/users.js` `GET /users` | Off-by-one in pagination — slice end is `start + PAGE_SIZE - 1` |
| 2 | Logic | `src/routes/users.js` `GET /users/:id` | Missing NaN/not-found guard — returns 200 with empty body |
| 3 | Security | `src/routes/users.js` `POST /users/login` | Plain-text password compare with `===` (no hash, no timing-safe equality) |

Baseline tests in `tests/users.baseline.test.js` (3 tests) **fail** on the seeded code and **pass** once the Bug Fixer applies the plan — verified: `Tests: 3 failed, 3 total` on the unpatched app. After a full pipeline run, `Tests: 26 passed, 26 total` (3 baseline + 23 generated by the Unit Test Generator in `tests/users.fixed.test.js`).

**Pipeline runner**

The pipeline is driven by the Claude Code conversation orchestrator (see `CLAUDE.md`). Invoking any entry-point agent in a Claude Code session auto-chains every subsequent step:

1. Validates each step's expected output file exists before launching the next agent.
2. **Hard stop** — if `verified-research.md` contains `Overall result: FAIL`, reports failure and stops before Bug Planner.
3. **Hard stop** — after Bug Fixer, runs `npm test`; if it fails, stops before Security Verifier and Unit Test Generator.
4. Reports a one-line status update after each agent completes.

Entry points: `@agent-bug-researcher <id>` runs the full pipeline; mid-pipeline entry points (`@agent-bug-planner`, `@agent-bug-fixer`, etc.) continue from that step forward.

## ⚠️ Challenges Encountered

### 1. Agents not visible in `/agents`

**Problem:** Initial implementation placed agents in `agents/*.agent.md` (as `TASKS.md` requires) and the runner used `claude -p --append-system-prompt "$(cat agent.md)"`. The agents worked end-to-end but did not appear in `claude agents` or the IDE `/agents` UI because Claude Code only registers files under `.claude/agents/` (or `~/.claude/agents/`) with the specific subagent frontmatter format.

**Solution:** Added parallel `.claude/agents/<name>.md` files with the Claude Code subagent schema (`name`, `description`, `tools`, `model`), moved orchestration into `CLAUDE.md` as auto-chaining rules for the conversation runner, and kept the original `agents/*.agent.md` because `TASKS.md` mandates that exact path. The two files for each agent carry the same role, model, and rules; the `.claude/agents/` copy adds the metadata Claude Code expects at runtime.

---

### 2. Pipeline must not fan out on a broken tree

**Problem:** A naive sequential runner would invoke Security Verifier and Test Generator even if the Bug Fixer left tests failing — producing nonsense reports on a half-fixed codebase. The spec's `Run order` line (`Security Verifier (on changed code) → Unit Test Generator (on changed code)`) implicitly requires a green tree before those steps run.

**Solution:** The conversation orchestrator runs `npm test` after the Bug Fixer step; if it fails, the orchestrator reports the failure and stops **before** invoking Security Verifier and Test Generator. The Research Verifier verdict gets the same treatment — `Overall result: FAIL` in `verified-research.md` aborts before Bug Planner.

---

### 3. Subagent role specs must live in two places at once

**Problem:** `TASKS.md` is explicit that agents are stored as `agents/<name>.agent.md`. Claude Code is equally explicit that subagents must live in `.claude/agents/<name>.md`. Different paths, different filename conventions, different frontmatter expectations.

**Solution:** Made `agents/*.agent.md` the **canonical role specifications** (matches `TASKS.md` and is what a grader will look for), and `.claude/agents/*.md` the **runtime definitions** (what `/agents` and the conversation runner consume). Documented this split in `README.md` under "Agent files" so it's not surprising to anyone reading the repo cold. In a subsequent session the two copies were **fully synced** — `agents/*.agent.md` now carries the same frontmatter (`name`, `description`, `model`, `tools`) as the `.claude/agents/` copies, so both directories are authoritative and consistent.

### Промпт 2 — Генерація всього додатку

**Промпт:**
```
створи додаток на Node.js відповідно до вимог які описані
```

**Що відбулося:**
На основі `CLAUDE.md` та `TASKS.md` Claude згенерував повноцінний додаток з нуля:

1. **`package.json`** — залежності: `express`, `uuid`; dev: `nodemon`
2. **`.gitignore`** — виключення `node_modules/`, `.env`
3. **`src/store.js`** — in-memory масив транзакцій із функціями `createTransaction`, `getAll`, `getById`. UUID генерується автоматично, `timestamp` — поточний час у ISO 8601
4. **`src/validators/transaction.js`** — валідація з повним списком ISO 4217 кодів валют (~150 кодів), перевірка формату акаунту через regex `ACC-[A-Za-z0-9]{5}`, валідація суми (позитивна, макс. 2 знаки після коми). Логіка валідації різниться залежно від типу транзакції
5. **`src/routes/transactions.js`** — три ендпоїнти: POST з валідацією, GET з фільтрацією (`accountId`, `type`, `from`, `to`), GET by ID
6. **`src/routes/accounts.js`** — баланс (сума всіх incoming мінус outgoing) та summary (Option A): підсумок депозитів, знімань, кількість транзакцій, дата останньої
7. **`src/index.js`** — Express app з монтуванням роутів та 404-catch-all
8. **`demo/run.sh`** — bash-скрипт для одноразового запуску
9. **`demo/sample-requests.http`** — 15+ готових HTTP-запитів для VS Code REST Client
10. **`demo/sample-data.json`** — приклади транзакцій
11. **`HOWTORUN.md`** — покрокові інструкції запуску

**Ключові архітектурні рішення AI:**
- Баланс рахується динамічно при кожному запиті (не зберігається окремо) — спрощує модель даних
- Для `deposit` `fromAccount` = null (не вимагається), для `withdrawal` `toAccount` = null — відповідає реальній банківській логіці
- Валідатор розбитий на допоміжні функції (`validateAmount`, `validateAccount`) для перевикористання

**Результат:** Повністю робочий API, перевірений smoke-тестами через curl.

### Промпт 3 — Рефакторинг: винесення бізнес-логіки в сервіси

**Промпт:**
```
винеси логіку з routes в окремий сервіс. Щоб самі роути виглядали clear
```

**Що відбулося:**
Claude провів рефакторинг без зміни поведінки:

1. Створено **`src/services/transactionService.js`** — містить `createTransaction`, `getTransactions` (з фільтрацією та валідацією дат), `getTransactionById`
2. Створено **`src/services/accountService.js`** — містить `getBalance` та `getSummary`; спільна логіка (`getAccountTransactions`, `calcBalance`) винесена у приватні функції всередині модуля
3. **Роути** зведено до мінімуму: отримати запит → викликати сервіс → повернути відповідь або HTTP-помилку

**Принцип поділу відповідальності після рефакторингу:**
- `routes/` — тільки HTTP: статус-коди, серіалізація, 404/400
- `services/` — бізнес-логіка: фільтрація, розрахунки, агрегація
- `validators/` — правила валідації вхідних даних
- `store.js` — єдина точка доступу до даних

**Результат:** Кодова база з чітким поділом шарів, легша для тестування та розширення.
